# 대항해시대 II (한글 DOS판) 역공학 노트

대상: `Portolan.zip`의 `GAME/`. 주소는 모두 `MAIN.EXE`의 **로드 이미지 오프셋**입니다 (파일 오프셋 = 주소 + 0x5400).
`DS`는 세그먼트 0x378B이므로 `DS:n`의 이미지 주소는 `0x378B0 + n`입니다.

표기: ✅ 구현으로 검증됨 / 🔎 코드에서 확인, 미사용 / ❓ 미해독

## 실행 구조

- `PLAY.BAT` → `FMDRV`(FM 드라이버) → `VOYAGE2.COM`(크랙 로더, PKLITE) → `OPEN.EXE` / `MAIN.EXE` / `END.EXE`
- `MAIN.EXE`: 16비트 MZ, 비패킹, 재배치 5250개, 세그먼트 5개 (0x0, 0xFB8, 0x1F74, 0x2DA1, 0x378B=데이터)
- 화면: VGA 모드 12h, 640×480 16색. 게임 내용은 640×400 영역
- 소프트웨어 인터럽트 0x65~0x67 등으로 드라이버 호출, `INT 67h`로 EMS 사용

## 압축과 그래픽

### LS10/LS11 아카이브 ✅ (`tools/ls11.py`)
`.LZW` 확장자이지만 LZW가 아니라 코에이 LS11입니다.

| 오프셋 | 내용 |
|---|---|
| 0x00 | `LS10` 또는 `LS11` + 0 12바이트 |
| 0x10 | 256바이트 사전 |
| 0x110 | BE u32 (압축크기, 원본크기, 오프셋) 반복, 0으로 종료 |

비트스트림은 MSB 우선입니다. 코드 읽기: 1비트씩 읽어 0이 나올 때까지 `a`에 쌓고(n비트), 다시 n비트를 `c`로 읽어 `a+c`.
값이 256 미만이면 사전 바이트, 이상이면 거리 `값-256`, 길이 `다음 코드+3`의 복사입니다. 14개 파일 전부 크기 일치.

### 압축 이미지 ✅ (`tools/gfx_codec.py`, 루틴 0xFC4)
`GRAPH.DAT`는 BE u32 오프셋 테이블 + 이미지 65개입니다. `EVENT*.DAT`, `GRAPH2.DAT`, `ENDGRP.DAT`, `OPGRAPH` 하위 파일도 같은 컨테이너로 보입니다 🔎.

`[u16le 폭(bit15는 플래그)][u16le 높이][u16le 사전 8개][스트림]`

스트림 단위는 4픽셀 폭 유닛이고, 유닛은 플레인별 니블 4개인 16비트 값입니다. 명령 바이트 `b`:

- `b & 0x80`: 복사. 개수 `(b&15)+1`, 거리 `((b>>4)&3)+1`. `b & 0x40`이면 위쪽 행, 아니면 왼쪽
- 그 외: 개수 `(b&7)+1` 필. `op = b&0x78`
  - 0 → 0, `op&0x40` → 사전[`(op>>3)&7`], 0x38 → 리터럴 2바이트(앞이 상위)
  - 0x08~0x30 → 1바이트를 니블 위치별로 배치 (점프 테이블 0x11AE)

0x12FD에 3플레인 변형(사전 없음)이 있습니다 🔎. GRAPH.DAT 65개는 0xFC4 형식으로 잔여 바이트 없이 디코딩됩니다.

### 팔레트 ✅
`0x40ECE`의 16색 × 3바이트, 순서 **B,R,G**, 채널당 0~15 (`shl 2`로 DAC 출력, 루틴 0x156B). 0x4238D 등에 장면별 변형 테이블이 더 있습니다 🔎.

## 월드맵 ✅ (`tools/worldmap.py`, 루틴 0x224E1 / 0x22734)

- 파일 하나 = 30×45 블록, 블록 = 12×12 셀, 셀 = 2×2 타일

  - `0x10, 0x11, 0x12`: 항구 / 보급지 레코드 조회 (해시 테이블 `[0x70C]`)
  - 그 외: `DATA1[18]`에서 칩 4개 조회
- 육지 칩은 위도별 0x41 / 0x49 / 0x51 (+ 사막 0x59). 해안 오토타일 0x219F8과 시야 칩 전체 ✅ — `docs/re/seamap.md`, `tools/seamap.py`, `WorldRenderer.swift`(ClassicMap)

## 항해 규칙 ✅ (`Sources/PortolanCore/Navigation.swift`)

방향은 8방위이며 0이 북쪽이고 시계방향입니다. 벡터 표는 `DS:0x754`(dx), `DS:0x75C`(dy)입니다.

### 시간
- 날짜 `[0x56E]` 경과 연도(52년이면 종료), `[0x56F]` 월(0부터), `[0x570]` 일, `[0x571]` 틱
- **하루 72틱** (0x1AC8F). 날씨는 12틱마다 재추첨 (0x1ACD1)

### 바람과 해류
- `WINDCUR.DAT` = 450B × 3: 여름 바람, 겨울 바람, 해류. 30×15 구역, 구역 하나가 72×72 타일
- 조회: `(y/72)*30 + x/72` (0x22A0D). 버퍼 `[0x43C]` 바람, `[0x440]` 해류
- 바이트: bit0-2 세기, bit3-5 방향(바람·해류가 향하는 쪽), bit6-7 사건 구역 플래그 (0x19474)
- 계절: 시작 시 3~8월이면 여름 표 (0x1604E). 이후 3월에는 여름, 9월에는 겨울 표로 교체 (0x17294)
- 일일 추첨 (0x199EC): 세기 `min(7, 기본 + rand(2))`, 방향 `기본 + (rand(3)-1)*(rand(5)>>2)` (mod 8). 해류는 고정
- 난수 (0x4D54): `seed = seed*0x41C64E6D + 0x3039`, 결과 `(seed>>16) & 0x7FFF`, `rand(n)` = 결과 % n

### 선속 (0x30C2F, 정보 화면용 간이판 0x1A69E)
각 배마다 아래를 계산하고, 함대 속도는 그중 최솟값입니다 (최소 2). 단위는 반 노트입니다.

```
d      = |풍향 - 침로|                     (0..7, 표가 대칭이라 랩 불필요)
풍력'  = 노선이면 max(풍력, 3)             (선종 플래그 0x10이 꺼진 배)
a      = 돛표[d][돛형식] * 추진력 * 풍력' / 150        (DS:0x714, 8×8)
a      = min(100, 선원배정% * 선원 / 필요선원) * a / 100
a      = min(150, 180 - 100*적재 / 적재한도) * a / 100
s      = min(30, a + a*항해레벨/10)
s      = min(40, s * 항해능력 / 75)
d∈3..5 이면 s = s * 선회력 / 100
```
- 무풍이고 노선이 없으면 0
- 적재량 (0x5C7F) = 식수/10 + 식량/10 + 자재 + 포탄 + 교역품 + 대포 + 선원

### 이동 (0x30E6E)
- 매 틱마다 축별 누산기 `+= 벡터[침로]*s + 벡터[해류방향]*해류세기`. 60에 도달하면 한 칸 이동 (대각선은 √2배)
- 막히면 x축만, 그다음 y축만 시도합니다 (0x30FCA)

### 하루 정산 (0x18F98)
- 소모 (0x18A3C 식량, 0x18AEE 식수): 배마다 `선원 * 배급량 / 100 + 1`통. 상륙 탐험 중(`[0xF91]&0x18`)이면 분모가 200입니다. 자기 배가 비었으면 함대의 다른 배에서 꺼내 씁니다
- 배급량 `DS:0x2D55` 식수, `0x2D56` 식량. 새 게임 값은 100
- 사기 (`화물레코드+0x1C`): `v = 100 - 통솔/5 - 배급량`. v>0이면 v/5만큼 감소, 아니면 |v|/10만큼 증가 (0~100)
- 굶주림: 사기 -16 (0x18B9E). 20 미만이면 선원 이탈 0x189FC (아래 '바다의 사건' 절)
- 쥐 떼 (0x18D3C, 메시지 473; 예전에 전염병으로 적었던 것): 출항 30일 초과 후 `rand(항해레벨/5+2)==0` 이고 `rand(105) > 운명`이면 발생. 고양이(아이템 25)가 있으면 생기지 않고, 쥐약(41)으로 없앱니다. 이후 매일 배마다 식량 1통을 갉아 먹습니다 (0x18DBE)
- 괴혈병 (0x18E20): 출항 60일 초과 후 `rand(105) > 운명`이면 발생. 이후 매일 `rand(2) + (100-지식)/5`명 사망
- 출항 일수 `DS:0x2D54`

### 레코드
- 선종 25개 `DS:0x5E28` × 12B: ❓, 내구, 선회, 추진, 대포, 필요선원, 적재(u16), ❓, 돛형식, 가격(u16)
  (내구는 1번 필드입니다. 조선소 생성 루틴 0x31C64가 `9 × [1] / 10`을 씁니다)
- 선박 `DS:0x57CE` × 25B: 이름[14], +0x12 선종, +0x13 플래그(0x10 = 돛 전용). 40~64번은 선종별 기본형
- 함대 `DS:0x2DB2` × 133B: +0 x, +2 y, +0x18/0x19 이동 누산기, +0x1A 침로, +0x2A 제독, +0x2B 배 슬롯 10×9B
- 배 슬롯 9B: 선원(u16), 내구, 최대내구, 선회, 추진, 대포, 선박번호, 플래그(`&0x30==0x10` 사용 중)
- 화물 `DS:0x5210` × 30B: 식수(u16), 식량(u16), 자재, 포탄, +9 선원배정%, +0xA 적재, +0x1B 항해사, +0x1C 사기
- 인물 `DS:0x1242` × 50B: +0x1C 통솔, +0x1D 항해, +0x1E 지식, +0x23 운명, +0x24 항해레벨
- 세이브 슬롯의 파일 오프셋 = DS 주소 - 0xB99 (인물·배급량으로 검증)

## 새 게임 상태 ✅ (`Sources/PortolanCore/Prologue.swift`)

- `DATA1.LZW` 15번 항목 = 새 게임 데이터 세그먼트, `DS:0xC30`부터
- 날짜 `DS:0xC36..0xC39` = 21, 4, 16, 24 (0x15AC6이 달력으로 복사). 연도 표시는 `+1501` (0x1DD78) → **1522년 5월 17일 8시**
- 소지금 `DS:0x123A` = 0
- 주인공 6명: 인물 0~5, 함대 0/10/30/50/40/20 → 리스본, 세빌리아, 런던, 암스테르담, 제노바, 이스탄불
- 조안의 화물 레코드에는 식수·식량 200이 남아 있지만, 배 주문 루틴이 이를 0으로 초기화합니다

### 시나리오 스크립트 VM (0x3287A)
- 명령 바이트 `[0xBC20]`, 0xC0~0xFF 디스패치 (테이블 0x3289E). 바이트 읽기 0x31ED0, 워드(BE) 읽기 0x31EE4
- `C0 n CC 00 p C8 hh ll C7`: 대사 출력 (말풍선 n, 초상 p, 문장 번호)
- `F9 cls x`: 배 주문 (0x31C64). 빈 슬롯에 내구 `9×선종내구/10`, 선회·추진은 선종값, 선원·대포 0, 상태 0x20(건조 중). 화물 레코드는 식수·식량·자재·포탄 0, `+8`=25, 선원배정 50
- `FA x hhll`: 건조 중인 배를 활성화(0x10)하고 문장 번호를 배 이름으로 붙임 (0x31DAC)
- `0C 00 hh ll` 뒤 `E6 00`: 소지금 가산으로 보임 (1000닢 지급 세 곳)
- `DC 00 n 00 i`: 아이템 지급으로 보임 (은제 머리장식)

### 조안의 프롤로그 (SNR1)
- 0x25C `F9 05 05`: 공작이 배를 주문 (49번 대사 직후)
- 0x5CD `FA 05 0084`: 조선소에서 인도. 132번 대사 = 『헤르메스Ⅱ세』, 카라벨 라티나
- 0x391: 카를로타가 공작이 맡긴 1000닢 전달 (필수)
- 0x47F: 사제의 1000닢 (받기·기부·거절 선택지)
- 0x96E: 마르코가 전하는 매달 용돈 1000닢 (조건부)
- 배는 선원 0명으로 인도되며, 주점에서 고용합니다 (아래 절)

## 항구 시장과 주점 ✅ (`Sources/PortolanCore/Market.swift`)

### 시장 레코드 `DS:0x697C` × 37B (0x5B9E, 항구 0~99)
현재 항구 포인터는 `[0xC6E2]`이며 입항 시 항구 번호가 100 미만일 때만 갱신됩니다 (0x86A1). 보급항(100번 이상)에서는 직전 시장 항구의 값이 그대로 쓰입니다.

| 오프셋 | 내용 |
|---|---|
| +0 | 경제력 (u16, 리스본 780), +2 이번 달 경제 투자 |
| +4 | 공업력 (u16), +6 이번 달 공업 투자 |
| +8..+0xD | 6개 나라의 지지도 (포르투갈, 에스파냐, 튀르크, 잉글랜드, 이탈리아, 네덜란드) |
| +0xE..+0x17 | 가격 지수 10개 (50 안팎) |
| +0x18 | 특산물 가격 (u16) |
| +0x1A | 특산물 상품 번호 (0xFF 없음) |
| +0x1B | 특산물이 나오는 경제력 / 10 |
| +0x1C..+0x20 | ❓ (지역, 아이템 번호 등으로 보임) |
| +0x21 | 교역 구역 번호 (0~12) |
| +0x22, +0x23 | ❓ |
| +0x24 | 술 번호 |

항구 레코드(`DS:0x5F54`) `+0x13 & 7`은 항구의 소속 나라입니다.

### 보급 (0x273FA)

### 선원 이탈 (0x189FC)
- 식량·식수를 내준 배의 사기가 20 미만이 되면, 먹은 배에서 `min(선원, (20 − 사기) × 선원 / 100 + 1)`명이 떠납니다 (사기는 먹은 배의 것). 최솟값이 부호 없는 비교라서 먹은 배의 사기가 높으면 음수가 커져 전원이 떠납니다 (원본 그대로)
- 사기 감소는 그 배 선장의 통솔을 씁니다 (화물 레코드 `+0x1B`의 인물)

### 사건 구역 (0x199EC → 0x19474)
- 날씨는 12틱마다 다시 뽑고(0x199EC), 그때마다 사건을 검사합니다. 사건 중에는 바람이 그대로 유지되고 구역 플래그와 해류만 바뀝니다
- 바람 바이트 bit7이 사건 구역입니다. 제독·부선장·수석항해사 중 최고 운 L, 함대 선수상 평균 F에 대해 `rand(155) > L+50`이고 `rand(11) > F`이면 발생
- 바람 bit6: 단역 선장의 배가 `rand(100) > 선장 운`이면 사라집니다 (0x1926E, 336)
- 해류 bit6-7 = 1 폭풍우(`rand(7)+3 ≥ 풍력`이고 `[0x1032]`=0), 2 무풍(`rand(6) ≥ 풍력`), 3 안개(`rand(10)==0`이고 `rand(6) ≥ 풍력`)
- 시작 (0x19377): 부선장·수석항해사 중 직감이 높은 쪽이 `rand(100) ≤ 직감`이면 미리 경고(340/344/348, 지식 70 미만이면 342/346/350). 다음 추첨 때 사건이 시작되며(352/354/356) 그날은 끝나지 않습니다 (`[0xC3F]` bit 0x80, 매일 지움)
- 폭풍우 (0x195AC, 추첨마다): 배마다 `d = min(10, (100 − 선장 항해) / (항해레벨/5 + 3) + 1) + rand(2)`, 원양 항해 플래그(배 레코드 `+0x13 & 0x40`)가 없으면 ×5. 내구 −d, 추진·선회 −d/2, 최대내구 −1(하한 선종 내구/4). 풍력 7. `rand(8)==0`이거나 구역을 벗어나면 끝(360)
- 내구 0이면 난파(358). 기함이면 게임 끝 (0x197DA, `[0x426]=0x18`)
- 무풍 (0x1985F): 풍력 0. `rand(20)==0`이고 구역 기본 풍력이 있으면 끝(362)
- 안개 (0x198D7): 다른 함대가 보이지 않습니다 (0x306C5). `rand(30)==0`이거나 구역을 벗어나면 끝(364)
- 입항하면 사건·쥐 떼·괴혈병이 모두 풀립니다 (0x1B709)

## 매달 (0x189DA)
- 0x1728C: 3월과 9월에 계절 바람이 바뀌고, 그 계절의 교역 면허(아이템 0x23~0x28)가 사라집니다
- 0x1730D: 은행. 잔고 `[0x123E]`(100닢 단위, 부호 있음)+`[0x1240]`에 예금 월 3%, 빚 월 10% 🔎
- 0x173CC: 시장 100곳의 경제력 += 경제 투자 / 300, 공업력 += 공업 투자 / 300 (상한 1000, 투자 누계 `+2`, `+6`은 0으로). 그리고 가격 지수 10개가 각각 `rand(5)+1`만큼 50 쪽으로 (50 초과면 빼고 아니면 더함)
- 0x18864: 동료 월급. 합계가 금화보다 많으면 아무도 받지 못하고(572) 각자 플래그 0x80. 이어서 충성 += `2 × 월급/10 − 능력 8개 중 최댓값 + 제독 통솔`, 0~100 (100이면 그대로)
- 0x184C1, 0x184D2, 0x1863C, 0x186DF: 나라 세력, 라이벌, 인물 이동 ❓

### 데이터 세그먼트 방식
리마스터는 원본 데이터 세그먼트 이미지(`assets/ds.bin`, 새 게임 상태)를 저장 데이터로 들고 다닙니다. 시나리오 스크립트와 함대 AI, 해전은 원본처럼 이 이미지의 레코드(인물, 함대, 항구, 발견지 등)를 직접 읽고 씁니다. 플레이어 쪽 상태(금화, 명성, 아이템, 동료, 배)는 Swift 모델이 가지며 스크립트 실행 전후에 이미지와 동기화합니다 (`ScriptSync.swift`).

## 원본과 다른 점 (리마스터)
- 항구 안 시간: 건물 출입에 원본처럼 2~4틱이 들고, 여관에서 숙박하거나 두 시간을 보낼 수 있습니다. 시가지는 원본처럼 걸어 다니며(town_walk.md), 걷는 동안 시간은 흐르지 않습니다
- 시가지의 시간대 색은 원본처럼 타일 색 8~15만 바꾸는 대신 창 전체에 색을 입힙니다. 원본에서 아무 키나 마우스 조준 방향으로 걷는 동작은 빼고, 지도에서 누른 방향(주인공 기준)으로 걷습니다. F1~F4 탭 단축키는 없습니다
- 시야 안 함대의 길찾기는 원본 그대로입니다 (도착하면 창 왼쪽 위로 향하는 버그 포함). 72×72 육지 격자는 창 위치마다 한 번만 만들어 둡니다
- 원본 시야 창은 720타일 단위 세 구역에 맞춰지지만 리마스터는 플레이어 블록 둘레 3×3 블록이라, 구역 경계를 넘기는 처리(0x239AE)는 쓰지 않습니다
- 나라끼리 항구를 빼앗는 코드(0x17AB4)는 원본에서도 실행되지 않습니다 (상태 바이트 전체를 4와 비교하는 버그). 리마스터도 그대로 둡니다
- 항구이동(자동 항해)은 원본처럼 해도에 기록된 항로 노드를 따라가고, 강 상류 항구의 마지막 구간과 좌초한 항로는 타일 단위 A*로 이어 갑니다. 봉쇄 경비병은 원본처럼 낮 동안 항구 사무소 문 아래에 서서 길을 막습니다
- 주점의 항해자 목록은 원본의 주점/여관 구분(+0x2F 비트 4) 없이 한곳에 모두 보입니다
- 해전 지도는 원본의 13×12 창 대신 배가 있는 영역을 확대해 보여 줍니다
- 조우 직전 함대 전투력(+0x28)을 다시 계산합니다 (원본은 처음 피해를 입기 전까지 0)
- 무국적 항구의 왕궁(나라 6)은 면허를 팔지 않습니다 (원본 경로 미추적)
- 감시는 원본처럼 화면 칸을 찍는 대신 시야 안 함대 목록에서 고릅니다
- 적하편성은 원본의 "미적재 적하" 풀 대신 배에서 배로 바로 옮기고, "버린다"를 고르면 풀에 남겨 버리는 것과 같습니다. 물·식량의 10분의 1통 단위가 잘려 나가는 규칙은 그대로입니다
- 승무원편성은 숫자 입력 대신 ±1·±10·전원·0 버튼으로 같은 공식(사기 가중 평균)을 씁니다
- 돛을 다 접으면 리마스터에서는 시간이 멈춥니다(일시정지 대용). 원본의 정박은 항해 메뉴의 "정박"이며, 이때는 원본처럼 시간이 흐르고 물자가 소모됩니다
- 시세·물가의 특산품 매입가는 원본 버그(10개 항구에서 교역 구역 슬롯 가격을 보여 줌)를 고쳐 특산품 자체 가격을 보여 줍니다
- 항해일지에는 원본과 같은 다섯 종류(입항, 출항, 해전, 항구 발견, 구입)만 적힙니다. "함대대"처럼 원본 문장 그대로 나오는 곳도 있습니다
- 오프닝: 타이틀 한자 안의 물결(팔레트 순환 대신 무늬를 흘림), 한자 섬광, 반짝임, 인물별 문장(권총·깃펜·동전·단검의 회전 프레임, 별, 동전, 불꽃)을 넣었습니다. 문장의 비행 경로(OPEN DS:0x518..)는 추적하지 않아 오른쪽에서 날아오게 했고, 자막의 반짝임은 페이드로 대신합니다. 키나 클릭으로 원본처럼 오프닝을 건너뜁니다
- 주사위 도박의 동점 처리는 원본의 이상한 결과 대신 tavern_more.md §9.5의 정상 결과(셋 동점, 나와 B 공동, B 승)를 씁니다. 카드와 주사위는 원본 그림을 추출하지 않아 글자와 시스템 아이콘으로 그립니다
- 지도를 눌러 잡은 항로(리마스터 전용 자동 항해)가 바람이나 해류에 밀려 해안에 붙은 채 이틀 동안 같은 칸에 머물면, 막힌 것으로 보고 한 번 다시 계획하고 그래도 안 되면 돛을 접습니다
- 안개 속 배 실종(바다 이변)은 원본처럼 배 레코드를 흘리지 않고 배를 제대로 지웁니다
- 효과음은 원작 FM 음색을 모델로 렌더링한 파일입니다(실제 칩 녹음과 비교하지 않음). 폭풍은 다른 효과음이 끝나면 다시 이어집니다
- 원작 화면 배치(선택)의 바다 지도 창은 원작처럼 함대가 여유 칸 11±[0xC35](해상이동치, 환경 설정)을 벗어날 때만 한 칸씩 따라가고, 720칸 3분할 경계에서는 원작처럼 창이 멈췄다가 다음 구역에서 다시 시작합니다. 리마스터는 함대가 연속으로 움직이므로 한 칸 이동을 짧게 미끄러지듯 보여 줍니다. 건물 창은 원작 메뉴 대신 리마스터 창을 화면 틀 위에 띄웁니다
- 원작 화면 배치의 대화창·메시지 창·팝업 메뉴는 원작 창(테두리 조각, 체크무늬 그림자, 빨간 ▼, 반전 선택, 회색 점무늬)을 그대로 그립니다. 예/아니오는 원작이 그림 상자(0x13FDB)를 띄우는 자리에 두 항목 팝업을 띄웁니다. 대본 창 위치는 DS:0xBBBA의 초깃값을 씁니다
- 원작 화면 배치의 해전은 13×12칸 전장과 오른쪽 패널(GRAPH.DAT 26)을 원작대로 그리고, MENU 50 명령 메뉴를 원작처럼 차례마다 마우스 위치에 띄웁니다. 작전(배별 지시)은 배 고르기→방침·방법·대상·위임 메뉴로 지원합니다(리마스터 화면은 시스템 메뉴). 메뉴를 닫은 뒤에는 패널을 누르거나 Esc로 다시 부르고, ←/→로 뱃머리를 돌리며 Return으로 정선합니다. 전장 칩은 리마스터처럼 홀수 열을 반 칸 내려 그립니다(원작은 칩은 정사각 격자, 배와 표시만 반 칸 내림)
- 바다 그림은 기본으로 원작 칩 지도(seamap.md)를 쓰고, 환경 설정에서 리마스터 셰이더 지도로 바꿀 수 있습니다. 원작의 72×72 창 경계에서 사막 채우기가 잘리는 현상(windowOverrides)도 함대가 그 창에 있을 때 재현합니다. 시간대 팔레트는 틱마다 한 단계씩 바뀝니다
- 원작 세이브(KOUKAI2.DAT)를 불러오면 데이터 세그먼트는 그대로 쓰고 Swift 쪽(배·동료·시장·날짜·위치·항해일지)을 다시 만듭니다. 배는 원작처럼 선장 기준으로 다시 배치합니다(주인공 배가 맨 앞, 동료 i−1이 배 i의 선장). 도크에 맡긴 배와 건조 중인 배는 옮기지 않습니다
- 배가 지날 수 있는 곳은 원작 규칙(칩 0x34 이상은 막힘)을 따르고, 원작처럼 함대의 2×2칸이 모두 바다여야 지나갑니다. 리마스터는 위치가 연속이라 2×2칸을 함대 그림의 중심 둘레로 잡고, 항구에서 막 나와 2×2가 들어가지 않는 자리에서는 한 칸 기준으로 빠져나가게 합니다
- 엔딩이 끝나면 원본처럼 이야기 모드를 끈 "엔딩 이후" 데이터를 슬롯 창에서 저장하고(원본은 엔딩 전에 저장) 타이틀로 돌아갑니다. 슬롯은 KOUKAI2.DAT 대신 슬롯별 JSON 파일입니다
